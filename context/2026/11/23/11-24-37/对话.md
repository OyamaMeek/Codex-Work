# 上海 VPS Komari 离线排查

## 用户

我一台上海的vps装了还是离线

附件：Komari 面板截图，Shanghai-Aliyun 显示离线、Unknown，资源及流量为零。

## 助手

妹妹，截图里 Shanghai-Aliyun 的系统信息和资源数据都为空，说明面板目前没有可用的上报数据。我先核对 Komari 的排查方式，具体原因还需要看上海 VPS 上的服务状态和日志。

## 助手

妹妹，我会按 systematic-debugging 技能，先检查 Agent 是否运行、能否连到面板，以及认证是否成功。

## 助手（请求排查输出）

请在上海 VPS 上运行下面三条命令，把完整输出贴给我；若输出含 token，请先遮住。

```bash
sudo systemctl status komari-agent --no-pager -l
sudo journalctl -u komari-agent -n 60 --no-pager
curl -4 -I --connect-timeout 10 --max-time 20 https://komari.hapanetwork.com
```

这三项分别检查服务状态、上报错误，以及上海 VPS 到面板的 IPv4 HTTPS 连通性。

## 用户

```text
root@localhost:~# sudo systemctl status komari-agent --no-pager -l
sudo journalctl -u komari-agent -n 60 --no-pager
curl -4 -I --connect-timeout 10 --max-time 20 https://komari.hapanetwork.com
Unit komari-agent.service could not be found.
-- No entries --
-bash: curl: command not found
```

## 助手

妹妹，这个输出确认了两件事：系统里找不到默认的 `komari-agent` 服务，也没有 `curl`，所以连通性检查还没执行。接下来需要核对安装过程；如果安装时没有自定义服务名，说明 Agent 没有成功注册为系统服务。

## 助手（后续操作）

妹妹，目前系统找不到默认的 Agent 服务，且缺少 curl。如果之前用 curl 下载安装脚本，下载这一步就无法执行。

如果这台是 Debian/Ubuntu，在当前 root 终端执行：

```bash
apt update && apt install -y curl ca-certificates
```

成功后进入 Komari 后台，找到现有的 Shanghai-Aliyun 节点，复制该节点的安装命令，在上海 VPS 上重新执行。随后运行：

```bash
systemctl status komari-agent --no-pager -l
journalctl -u komari-agent -n 30 --no-pager
```

把安装过程中的报错和这两条输出贴来，遮住 token。若安装时自定义了服务名，请同时说明。
